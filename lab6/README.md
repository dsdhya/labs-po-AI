# Лабораторная работа №6: Метод опорных векторов (SVM) и Ядерный трюк

## Описание
Датасет **E-Commerce Shipping Data** (`Train (1).csv`, 10 999 заказов; https://www.kaggle.com/datasets/prachi13/customer-analytics).  
Выбранные числовые признаки: `Discount_offered` (скидка) и `Weight_in_gms` (вес товара в граммах); целевая переменная — `Reached.on.Time_Y.N` (`1` — доставка не вовремя, `0` — вовремя).

**Бизнес-задача:** заранее выявлять заказы с риском задержки доставки, чтобы логистика могла контролировать проблемные отправления.

## Структура
1. `README.md` — описание и выводы.
2. `Train (1).csv` — данные о доставке заказов.
3. `lab6.ipynb` — исполненный ноутбук (масштабирование, Linear vs RBF SVM, анализ доли опорных векторов, эксперимент с `C=0.01` и `C=1000`, визуализация границ).
4. `requirements.txt` — зависимости.

## Результаты
* `SVC(kernel="linear", C=1.0)`: точность **66.9%**
* `SVC(kernel="rbf", C=1.0)`: точность **67.9%**, опорных векторов — **5667 из 8249 (68.7%)**
* `SVC(kernel="linear", C=0.01)`: точность **67.1%** (6082 опорных вектора)
* `SVC(kernel="linear", C=1000)`: точность **66.9%** (5964 опорных вектора)

## Выводы
* **Влияние ядра:** ядро `RBF` дало прирост точности на 1% по сравнению с `linear` (`67.9%` против `66.9%`), так как граница между классами нелинейна.
* **Опорные векторы:** почти 69% обучающих заказов оказались опорными — при маленьких скидках классы сильно пересекаются. Остальные ~31% заказов (в основном с крупными скидками) модель уверенно отделяет и игнорирует при построении границы.
* **Параметр C:** завышение штрафа до `C=1000` не даёт выигрыша на шумных данных; мягкий зазор (`C=0.01`) работает чуть стабильнее (`67.1%`). Для более высокой точности стоит добавить к весу и скидке способ доставки и блок склада.
